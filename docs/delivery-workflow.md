# Prototype delivery workflow

Approved process amendment: `J-20260907-14`, ROADMAP 1.3. This changes delivery
order and coordination, not product semantics or evidence gates. The template
remains PRE-CLOCK; launch a separate product repository before building it.

## One launch decision, separate permissions

Record the owner's requested repository, visibility, `full` or `hackathon`
profile, implementation scope, hosting permission, and finite provider budget
once with the [launch CLI](./launch-cli.md). Default to private, no deployment,
and zero provider spend. A build request authorizes ordinary implementation
inside its scope, not publicity, production access, spending, or participant
contact. Missing external permission blocks that action, not safe local work.
Do not repeat approval questions already answered; reopen only a changed
boundary or a human gate.

Preflight GitHub identity, template generation readiness, toolchain, optional
control entitlements, Vercel linkage/build settings, and Gateway prerequisites
before choosing adapters. Reuse a ready indexed documentation corpus; search
the relevant provider subtree and inspect the underlying schema only when
necessary. Do not re-ingest or load entire manuals.

Use Vercel AI Gateway as the initial text-generation transport candidate, not a
direct-provider implementation that must later be replaced. Voice retains its
separate EXP-004 transport decision. Freeze endpoint, model, provider
restriction, request/response schema, authentication precedence, and admission
contract before dispatch. Credential presence and pricing are not proof of
working authentication, atomic admission, or a hard spending bound. No retries,
fallback model, or unbounded live request may be introduced for convenience.

Use the [Next.js REST helper](./deploy-cli.md) for explicitly authorized
provisioning/deployment and bounded build/runtime/access observation. Resume
known operations rather than blindly repeating creates. Preserve exact
repository/project identity, protection, and stable origin; sanitized receipts
are evidence artifacts, not a second routine status tracker.

## Deliver one observable path first

One implementer owns the first complete creative loop. Parallel lanes are
optional for genuinely independent work, not a default coordination structure.
Use the prepared library example: cards the AI sees -> develop a direction ->
change a constraint -> compare the child with its unchanged source.

| Checkpoint | Required observation or intervention |
|---|---|
| T+10 minutes | Platform prerequisites resolved and, if authorized, exact-revision shell Preview/access checked; otherwise name the specific blocker and continue local work. |
| T+20 minutes | One editable card is visible, movable by keyboard, durably acknowledged, and survives reload. If absent, stop breadth work and put the integration owner on this path. |
| Next vertical slice | Exact Focus-plus-target receipt, bounded Branch, atomic result placement and durable landing, then a second iteration from changed context. |
| Every 10 minutes | Emit a compact generated status: visible outcome, current blocker, next milestone, and implemented/integrated/live/accepted states. |
| After 5 minutes blocked | Review the critical dependency; repair, reassign to the integration owner, or explicitly retain the permission/evidence blocker. No unrelated polish. |

These are intervention thresholds, not promises to finish the full prototype
in twenty minutes. Build only the kernel and adapters required by the current
path, while retaining immutable content, precise authority revocation, durable
acknowledgement, recovery, accessibility, and exact context. An honestly labelled
simulation may prove local integration; it cannot earn live-provider evidence.
Prove one real bounded Branch before expanding live AI capabilities. R5 and
R6.9 still govern Searchlight and Voice expansion in the full profile.
As soon as the opening interaction exists, obtain an uncoached comprehension
observation before polish or Searchlight: can the person predict context,
the next action, and what remains unchanged? Record `not evaluated` if no human
is available. Keep the final exact-deployment reviewer exercise as well.
Do not restart approved design or repeat broad research after its runtime
contract is known.

## Bounded workers, one event record

Freeze the shared port signature, owned paths, acceptance case, and control
revision before dispatch. One owner integrates; workers do not edit shared
contracts, package metadata, or the same paths. Prefer direct work for small
tasks. Workers take units of at most five minutes, explicitly acknowledge the
current revision, and return a stable handoff before another unit.

Use the [process CLI](./process-cli.md) for machine-timestamped events, worker
control, status, timeline, and feedback. It is the single routine progress
source; generated reports are disposable. Launch configuration is a permission
record, not another progress tracker. Keep runtime artifacts in ignored
`.minerva/`; publish only reviewed, content-free evidence.

A sent message is not an acknowledged scope change. Pause/revise control before
dispatching replacement work; reject stale handoffs. Use guarded execution for
worker commands. Its termination boundary is documented in the CLI reference:
it is not an interrupt for arbitrary editor tools, remote agents, or external
requests. Unwrapped agents must finish their short unit and acknowledge pause
before replacement ownership starts. Never infer that a queued message stopped
them; preserve their branch and exclude unacknowledged output from integration.

## Freeze, prove, review, deliver

Exercise the [portable contract fixtures](./contract-fixtures.md) as soon as an
adapter exists. Template harness self-tests are not product conformance or
native browser evidence. Fix a material failure with its targeted regression;
do not re-run unrelated suites after each small patch.

Before review, freeze one complete integration batch: exact revision, changed
paths, port/schema revisions, UI-to-adapter wiring, durable landing behavior,
checks and results, external activation state, and known limitations. The
integration owner must prove the user journey, not concatenate worker reports.
Then run one full-state independent correctness review of the frozen diff.
Repair material findings with targeted regressions; re-review only the changed
boundary unless a finding invalidates broader evidence. No concurrent editing
of the reviewed batch. Required exact-head CI remains a merge gate.

Report **implemented**, **integrated**, **live**, and **human accepted**
separately. READY is not authenticated access; a response is not durable landing;
tests are not human product acceptance. Implementation delivery may finish while
live activation or owner evaluation is blocked, but the full roadmap is not
closed until its terminal evidence exists. Keep consequential decisions in
`JOURNAL.md` and gate transitions in `CURRENT_GATE.md`; neither is a manual
copy of the event stream.

Operational tooling stays content-free before launch. Do not prebuild workspace
persistence/provider functionality, import a passage-first interface, substitute
Gateway soft budgeting for atomic admission, apply Vite settings to Next.js, or
add a separate local server. Protected Preview alone does not satisfy reviewer
access or the stable-browser-origin requirement.
